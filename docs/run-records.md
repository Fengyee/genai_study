# 保存一次命令的成功、失败与耗时

长实验需要在开始前留下配置，并在结束后保存完整退出状态。`genai_study.run_record`使用Python标准库，适用于本仓库的Linux环境；它为一次子命令建立独立记录目录，保留合并的标准输出/错误日志和命令外层耗时。

完成README的安装后，可先用无需模型的命令验证路径：

```bash
python -m genai_study.run_record --timeout 5 \
  --output artifacts/run-record-demo -- \
  python -c "print('recording works')"
```

`--`前的参数属于记录器，后面是实际执行的程序及其参数。记录器直接传递argv；需要管道或重定向时，将操作写成可审查的脚本再运行。`--timeout`以秒为单位，必须为有限正数。子命令的标准输入连接空设备，适合本仓库无需交互的前台实验；Python子命令加`-u`可及时刷新日志。

## 两个目录各自保存什么

记录目录在子命令启动前创建，已有路径会使记录器退出；子命令自身的输出目录仍由实验入口管理。例如[10章](chapters/10-pretrained-video-lab.md#5-两个随机流与分阶段运行)的`artifacts/run-records/svd-smoke`保存运行记录，`artifacts/svd-smoke`保存帧和模型指标。重跑时同时选择新的记录目录和实验输出目录。

| 记录文件 | 内容与读取时机 |
| --- | --- |
| `run.json` | 启动前写入argv、工作目录、UTC开始时间、超时、记录器源码SHA及可用的Git HEAD/工作树状态；结束后补充状态、实际退出码、UTC结束、外层耗时及日志SHA |
| `command.log` | 子命令的stdout与stderr合并输出；失败和超时的已写日志也会保留 |

记录器打印记录位置与完成摘要。长实验进行时，可在另一个终端查看日志：

```bash
tail -f artifacts/run-records/svd-smoke/command.log
```

`wall_seconds`从启动子命令之前计到退出和回收结束，包含子进程的导入、文件校验、模型加载、推理与保存；超时后的终止宽限也计入。记录器自身的导入和初始元数据写入另有开销。[09章](chapters/09-pretrained-image-lab.md#6-先核对记录再评价结果)的模型内部推理计时与这个外层口径分别使用。

## 根据状态恢复

| `status` | 含义与下一步 |
| --- | --- |
| `running` | 子命令已准备启动，尚无结束记录。先检查进程与日志；宿主机中止、记录器被SIGKILL或断电后也可能保留此状态 |
| `succeeded` | 子命令退出0。接着检查实验输出、指标与全部样本 |
| `failed` | 子命令非零退出。按`command.log`定位参数、资产或运行错误 |
| `launch_failed` | 程序未成功启动。核对可执行文件、路径与权限 |
| `timed_out` | 达到本次时间上限，记录器终止进程组并返回124。先检查已保存日志，再调整配置或预算 |
| `interrupted` | 记录器收到SIGINT或SIGTERM并清理子进程，分别返回130或143。保留本次记录，再决定恢复方式 |

`child_returncode`保存子进程的实际返回值；Python用负数表示信号终止，例如`-15`表示SIGTERM。`exit_code`保存记录器向调用方返回的状态，超时时固定为124；普通程序退出则沿用其退出码，子进程自行被信号终止时返回`128+信号编号`。记录器先向同一进程组发送SIGTERM，最多等待1秒后发送SIGKILL并回收直接子进程。主动脱离这一进程组的程序需要自己的生命周期管理；本仓库实验沿默认进程组执行。

记录器保存命令参数和日志；权重身份、依赖版本、实际默认参数、随机输入和模型阶段计时继续从成功实验的`metrics.json`读取。源码身份用于定位当时的实现，修改后的工作树应另行提交或保留diff。记录状态与模型结果一起解释，运行成功后仍按章节的观察协议评价生成质量。
