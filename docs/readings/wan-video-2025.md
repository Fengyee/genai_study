## 2. 带着三个问题读核心结构

| 研究问题 | 原文定位 | 已核对的事实 | 可以进一步追问什么 |
| --- | --- | --- | --- |

### 表示：压缩率不是一个脱离通道数的数字

论文 Fig.5 使用输入帧数 $`F=1+T`$。在 $`T`$ 可被 4 整除、高宽可被 8 整除的情形，潜视频形状为

```math
F\times H\times W\times3
\quad\longrightarrow\quad
\left(1+\frac{F-1}{4}\right)\times\frac H8\times\frac W8\times16.
```

这里用 $`F`$ 表示帧数，避免与本仓库 DDPM 的总步数 $`T`$ 混淆。首帧单独处理，不能直接把所有帧数除以 4。§4.2.1 进一步用 $`(1,2,2)`$ 的 patch kernel/stride 形成视频 token；当高宽可被 16 整除时，

```math
L=\left(1+\frac{F-1}{4}\right)\frac H{16}\frac W{16}.
```

**独立算例**：$`F=81,H=480,W=832`$ 时，潜视频有 $`21\times60\times104\times16=2,096,640`$ 个标量，DiT 有 $`L=32,760`$ 个视频 token。相对 RGB 输入，标量数约减少 46.29 倍，既不是 256 倍，也不是端到端加速比。这是由结构公式推得的数量，不是显存或延迟实测。

“causal VAE”约束编码/解码中的时间依赖，不表示后面的 DiT 是逐帧自回归模型。报告 §4.3.1（p.15）明确讨论 DiT 的非因果注意力。VAE 能分块处理较长输入，也不能推出整个生成系统能在固定成本下生成无限长、始终一致的视频。

### 训练：与你已经实现的 Flow Matching 对照

报告 Eq.(1)–(3) 采用噪声 $`x_0`$ 到数据潜变量 $`x_1`$ 的路径

```math
x_t=(1-t)x_0+t x_1,\qquad v_t=x_1-x_0,
\qquad L=\mathbb E\|u_\theta(x_t,c,t)-v_t\|^2.
```

它与第 03 章的生成时间方向一致，但论文用 **logit-normal 时间采样**；本仓库二维实验使用均匀时间。网络结构、训练数据、表示尺度与资源也不同，不能将 toy 实验称为 Wan 的缩小复现。

阅读时以给出的目标和假设为准：回归速度的 MSE 不是代码已经计算出的精确负对数似然。对正文中的宽泛理论表述，应回到 Flow Matching 原始论文的条件目标等价性与正则性前提核对，而不要把“使用 FM”直接转写为“直接最大化精确似然”。

### 条件：接口是模型的一部分

I2V 使用首帧及填零视频构造条件潜变量，用掩码指示已知位置与待生成位置。报告的通道计数为 $`2c+s`$，其中 $`c=16`$、时间 stride $`s=4`$，得到 36 个输入通道；T2V 潜视频输入是 16 通道。这个差异解释了为什么不能仅修改命令行任务名就让 T2V 权重成为 I2V 模型。

官方 README 的下载表区分 T2V-1.3B、T2V-14B 与 I2V-14B 的 480P/720P 变体。实际实验还要固定对应权重 revision、帧数、分辨率、引导参数和采样器，不能只写“用了 Wan2.1”。

## 3. 如何阅读效果证据与限制

- **表示质量不等于生成质量。** §4.1.4、Fig.7（p.12）比较 200 段、25 帧、$`720\times720`$ 视频的 VAE 重建与速度。它主要回答表示层问题；不同模型的压缩率和潜通道数也需一并核对。
- **总分依赖评价协议。** §4.6–4.7.1（pp.20–22）、Table 2 描述 Wan-Bench：动态、图像、指令三个大维度，包含学习型评估器和人类偏好导出的权重，T2V 比较使用 1,035 个提示。这里记录的是作者的评价设计，不把报告中的排序当作今天的独立排行榜。
- **评估器不是物理证明。** 报告用视觉语言模型检查部分物理/动作问题；这是一个可出错的观测通道。应使用第 05/06 章的退化对照、具体事件规则与盲评检查其盲点。
- **作者承认的限制。** §6（p.47）列出大运动中细节保持、计算成本和特定领域能力不足。论文展示成功样例，不足以估计所有场景的失败率。

报告存在内部记载需要谨慎：Table 5（p.25）行标为 10k/15k steps，而紧接着 p.26 的正文写 100,000/150,000 steps。本文不据此给出该消融的精确训练预算，也不代作者选择其中一项；需要原始配置或作者澄清后再复现。这是阅读时应记录、而不是默默“纠正”的证据差异。

## 4. 代码、权重和成本分别记账

**许可核对**：固定 commit 的 [LICENSE.txt](https://github.com/Wan-Video/Wan2.1/blob/9737cba9c1c3c4d04b33fcad41c111989865d315/LICENSE.txt) 是 Apache-2.0 正文；同版 README 明示仓库模型采用 Apache-2.0。单独核对的 T2V-1.3B 模型卡，其 `license` 字段也为 `apache-2.0`。这不代表已审核所有后续衍生权重、第三方文本/图像编码器、训练数据或演示素材的许可；准备运行时，应为实际使用的各项工件分别记录来源与条款。源码公开也不证明完整训练数据已公开或数据权利问题已自动解决。

**作者报告、非本仓库实测**：固定 README 给出 T2V-1.3B 约 8.19 GB 显存，以及 RTX 4090 生成 5 秒 480P 视频约 4 分钟的说明。其计算效率一节还注明单卡 4090 的配置使用 `--offload_model True --t5_cpu`，未开启 prompt extension；不能将 GPU 显存数字当作整机内存需求，或据此承诺初始 CPU 云环境可运行。报告 §6 对 14B 提到未额外优化时单张高端 GPU 约 30 分钟，但没有在这句话中列全硬件与采样配置，因此它不适合作为可直接复现的预算表。

本仓库此轮只进行了文献和源码读取，没有下载权重、安装 Wan 的依赖、运行外部 API 或执行其推理。具备算力后，第一步应是按单一固定配置测量一次实际运行，再决定更多提示/种子的预算；不要先承诺按作者速度完成大批实验。

## 5. 练习：把阅读变成可证伪的问题

### A. 检查 token 数，而不是背诵压缩率

对 $`81\times480\times832`$ 视频，若仅把高宽同时翻倍，帧数不变，视频 token 数与朴素密集注意力矩阵元素数各变多少？

**答案**：token 数乘 4，密集注意力矩阵元素数乘 16。实际延迟/显存还受算子、激活保存和并行方式影响，不应据此直接宣称运行慢 16 倍。

### B. “VAE 更好”应怎样被反驳？

有人根据重建 PSNR 改善，宣称生成的视频运动一定更好。设计最低限度的分解实验。

**提示/答案**：先用同一组未训练视频测编码再解码的空间与时间错误，区分表示上限；再比较在各自兼容表示中训练的生成器，并固定训练资源和评价条件。不能直接互换不兼容 VAE 权重，否则潜尺度、通道或解码映射改变，会混入新的分布偏移。PSNR 改善若不伴随已定义的运动任务改善，就反驳“一定更好”。

### C. prompt extension 是隐藏变量吗？

同一 checkpoint 下，A 使用原始提示，B 让另一个模型扩写提示，然后 B 的指令遵循分数更高。这个结果证明什么？

**答案**：首先证明的是这两个完整输入流程在指定条件集上的差异，而不是底层视频权重自身改善。应保存原始与扩写文本，固定初始噪声、采样器和预算，同时计算扩写的成本及语义偏移；不要默默把外部模型调用纳入“同模型公平比较”。

### D. 一个尚未执行的研究计划

从 [论文阅读模板](../reading-paper-template.md) 开始，预先选择 12 个含明确运动方向/遮挡事件的条件，每条件 3 个 seed，只比较同一已许可模型的两种引导强度。保存完整视频，盲评动作完成度与身份稳定性，报告每条件配对差值及失败，不仅报告总平均分。

这只是 **72 段视频的实验设计**，不是已完成评测或成本承诺。先测一段，再决定是否缩小规模；若修改了扩写文本、帧数或 fps，应将其作为额外实验因素记录，而不能把所有变化归因于引导强度。
