# 07 · 从二维点到小图像：条件 Flow Matching 实验

**先修与依赖：** [03 Flow matching](03-flow-matching.md) 的直线路径与 Euler 采样、PyTorch 卷积和广播；建议先完成 [05 评价与实验诊断](05-evaluation.md)。

**完成后应能：** 把二维速度回归推广到 `B,C,H,W` 图像张量；解释时间、类别和坐标怎样进入卷积网络；从原始数值、形状与多样性三个角度检查生成结果。

**实践产物与范围：** 在 CPU 上从零训练一个小型条件卷积网络，生成 $16\times16$ 的圆盘和轴对齐方形。图像由本仓库程序绘制，无需下载数据、预训练权重或调用付费 API。这里确实有一个学习参数的图像生成器，与 [06 章](06-video-temporal-lab.md) 无需训练的时序反例不同；它仍只面对受控几何图形，不代表真实图像、文字到图像或视频生成能力。

## 1. 算法没换，变量的结构变了

03 章中每个样本是二维点。本章每个样本有 $C\times H\times W=1\times16\times16=256$ 个标量，但保留其空间排列：

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| 干净图像 $y$、高斯噪声 $z$ | `B,1,16,16` | 一批单通道图像；batch 维不是图像的一部分 |
| 随机时间 $t$ | 每样本一个标量，广播为 `B,1,1,1` | 同一图像所有像素使用同一个路径时间 |
| 带噪图像 $x_t$、速度目标 $y-z$ | `B,1,16,16` | 维度相同，语义不同 |
| 类别 $c$ | `B` | `0` 表示圆盘，`1` 表示轴对齐方形 |
| 网络输出 $v_\theta(x_t,t,c)$ | `B,1,16,16` | 每个像素的强度变化率，不是类别概率 |

图像可以展平成 256 维向量使用 03 章公式；卷积网络选择保留网格结构以利用局部模式和参数共享。张量维度匹配只是一项必要检查：把 `B,H,W,C` 误当 `B,C,H,W`，或者给每个像素独立采样时间，可能仍有某种合法运算，却已经不是这里声明的模型。

## 2. 教学数据是怎样画出来的

每次训练重新采样几何参数，再在像素坐标上计算软边图像。类别在 batch 中平衡；数据生成过程没有使用外部图像。

| 对象 | 本章配置 |
| --- | --- |
| 分辨率与通道 | $16\times16$、单通道，像素强度位于 $[0,1]$ |
| 中心 | 水平和垂直坐标在 $[5,10]$ 像素范围内采样 |
| 尺寸 | 圆盘半径或方形半边长在 $[2,3.5]$ 像素范围内采样 |
| 边缘 | 以 0.35 像素作为 sigmoid 软化尺度 |
| 类别 | 圆盘 / 轴对齐方形，无旋转、纹理、文字或自然图像背景 |

以像素位置 $(j,i)$、中心 $(c_x,c_y)$ 为例，圆盘可用内部为正的轮廓函数

$$
h_{\mathrm{disk}}(i,j)=r-\sqrt{(j-c_x)^2+(i-c_y)^2}
$$

描述，方形则用

$$
h_{\mathrm{square}}(i,j)=r-\max(|j-c_x|,|i-c_y|).
$$

像素取 $y_{i,j}=\operatorname{sigmoid}(h(i,j)/0.35)$。方形的表达式沿角外方向不是欧氏有符号距离；这里使用它的等值线定义软化方形，不能据此推断边缘在所有方向具有完全相同的欧氏厚度。

**为何用软边？** 它使亚像素位置和尺寸变化能连续影响像素值，减少硬阈值栅格化的突变。但这些图像仍集中于极少数几何参数形成的低维集合，并非自然图像分布。在线无限次采样也不意味着任务具有无限语义或足够复杂的泛化要求。

类别条件是形状，中心和尺寸没有作为条件传给网络。因此本章要学的是 $p(y\mid c)$：给定“圆盘”后，仍应生成多种位置和大小，而不是永远输出同一个圆盘。

## 3. 带类别条件的直线路径

沿用 03 章的方向：$t=0$ 是噪声，$t=1$ 是数据。独立采样 $z\sim\mathcal N(0,I)$、$y\sim p_{\mathrm{data}}(y\mid c)$，并采样 $t\sim\operatorname{Uniform}[0,1]$：

$$
x_t=(1-t)z+ty,\qquad u_t=y-z.
$$

与 03 章不同的是网络额外看到 $c$。平方损失的理想回归解为

$$
v^*(x,t,c)=\mathbb E[y-z\mid x_t=x,t,c].
$$

条件 $c$ 可以缩小目标的不确定性，但给定 $x_t,t,c$ 后仍可能对应很多噪声和干净图像组合，因此最优 MSE 一般不为零。这不是因为模型忘记了一张“唯一正确图像”。

### 范围不同，不需要强行相同

干净像素位于 $[0,1]$，标准高斯噪声却没有有限取值范围；它可以为负，也可以大于 1。中间的 $x_t$ 和速度目标 $y-z$ 因而都不受 $[0,1]$ 限制。

训练时不能把 $z$ 或 $x_t$ 随手 `clamp(0,1)`：这会改变声明的概率路径。网络最后一层也不应只因为数据是图像就添加 sigmoid；它预测的是可正可负的速度，不是最终像素。图像缩放到 $[-1,1]$ 也可以定义一个合理任务，但必须同时修改数据、诊断和实验记录，不能把两套尺度下的 MSE 直接比较。

### MSE 到底除以了什么

实现对 batch、通道和空间位置全部求均值：

$$
\widehat L=\frac{1}{BCHW}\sum_{b=1}^B\sum_{k=1}^C\sum_{i=1}^H\sum_{j=1}^W
\left(v_\theta(x_t,t,c)_{b,k,i,j}-(y-z)_{b,k,i,j}\right)^2.
$$

对于固定图像大小，这与“每图求平方和再对 batch 求均值”的目标相差常数 $CHW=256$，理想最优解相同，但梯度尺度与优化器行为不必相同。不要把这里的像素均值 loss 与 03 章的二维 loss 当成难度或模型质量的直接排行榜。

像素均值还容易被大面积背景主导：少量边界和前景错误可能在全图平均后变小。因此需要查看完整样本、形状诊断以及前景统计，而不只看训练曲线。

## 4. 卷积网络怎样接收时间与条件

本章使用一个很小的 U-Net 风格卷积网络：空间下采样使信息覆盖更大的区域，恢复分辨率时结合浅层特征。它的目标是展示空间结构和条件输入，而不是复现 LDM、DiT 或某个大型图像模型。

输入不只有带噪图像。时间、one-hot 类别和坐标被展开为空间通道，与图像拼接：

| 输入部分 | 通道数 | 作用 |
| --- | --- | --- |
| 带噪图像 $x_t$ | 1 | 提供当前状态 |
| 时间 $t$ | 1 | 告诉网络当前处于路径哪一段 |
| 类别 one-hot | 2 | 区分圆盘和方形 |
| 水平 / 垂直坐标 | 2 | 提供图像中的位置 |

因此第一层看到 6 个通道，输出仍只有 1 个速度通道。条件通道不是额外要生成的图像，也不是将类别重复当成多个训练样本。

卷积核共享参数，利于复用局部边缘模式；下采样和多层组合扩大有效感受野。但“使用卷积”不等于模型对任意平移严格等变：有限边界、padding、下采样及显式坐标通道都会影响这一性质。坐标通道还提供绝对位置，帮助模型利用教学数据的中心范围；这种设计假设不应未经检查就搬到另一套数据。

本章只训练有条件速度场，没有训练无条件分支，也没有 classifier-free guidance。两个类别的一次条件编码不等于自然语言条件系统。

## 5. 从安装到一组可检查的图像

先完成 [README](../../README.md) 的安装并激活环境，在仓库根目录运行：

```bash
python -m genai_study.image_flow --help
python -m genai_study.image_flow --steps 1500 --seed 7 --output artifacts/image-flow
```

若只需排查环境和文件输出，先进行低预算 smoke：

```bash
python -m genai_study.image_flow --steps 20 --samples 16 \
  --sampling-steps 8 --seed 7 --output artifacts/image-flow-smoke
```

20 次更新只检查训练、采样和保存能否完成，不是图形可识别性或收敛测试。使用不同输出目录保存不同实验；不要把后来较好的图覆盖掉失败证据。

### 命令接口

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--steps` | `1500` | 优化器更新次数，与采样步数不同 |
| `--batch-size` | `64` | 每次更新的图像数量 |
| `--samples` | `128` | 生成与诊断的样本数量 |
| `--sampling-steps` | `40` | 显式 Euler 积分步数，等于本实现的 NFE |
| `--seed` | `7` | 本次训练与生成随机性的基础种子；跨平台位级一致性不保证 |
| `--threads` | `1` | CPU 线程数 |
| `--output` | 必须按命令指定或核对 `--help` | 结果目录 |
| `--overwrite` | 默认关闭 | 明确允许覆盖该输出目录中的已有实验文件 |

优化器为 Adam，学习率 $10^{-3}$，基础卷积宽度为 16。GPU、混合精度、任意图像目录输入和文本提示不是本章接口。实际版本和每次配置会写入 JSON；成本和多种子观察见[图像实验报告](../image-experiment-report.md)。程序输出文件不能单独证明生成质量达标。

### 采样

给定类别 $c$，从新的高斯图像噪声出发，执行

$$
x^{(k+1)}=x^{(k)}+\frac1K v_\theta\left(x^{(k)},\frac{k}{K},c\right),\qquad
k=0,\ldots,K-1.
$$

每一步更新所有像素。生成过程中不裁剪状态；积分结束后保留原始输出。由于有限训练、数值误差和模型结构，像素可能越过 $[0,1]$。这也是需要记录的现象，而不是保存图片时偷偷抹去的问题。

这个独立实验模块目前不保存可复用模型 checkpoint，不能把其结果直接传给 03 章的 `solver_study`。重新训练多个配置会同时改变模型与采样器，不构成“冻结同一模型”的严格求解器对照。

## 6. 输出、诊断与通过标准的局限

| 文件 | 读者应检查什么 |
| --- | --- |
| `metrics.json` | 配置、版本、训练/采样成本与每类诊断；精确字段以当次文件为准 |
| `arrays.npz` | 保存的数值数组，用于复核而不只看渲染图片 |
| `samples.png` | 圆盘与方形的样本是否可辨、是否响应条件，位置与大小是否变化 |
| `loss.png` | 优化是否正常；下降不等于几何正确或分布覆盖充分 |

### 先看未裁剪数值

可视化和几何模板诊断使用裁剪到 $[0,1]$ 的图像，同时单独报告原始输出的越界比例与平均裁剪幅度。若原始输出为 1.8，展示图中的白色看起来可能正常；仅检查展示图就看不到这个误差。裁剪是一种输出处理，不是训练网络已经学会约束范围的证据。

### 再看是否接近声明的几何族

本实验使用一组已知圆盘和方形模板：中心以 0.5 像素间距、尺寸以 0.25 像素间距枚举。每张输出对各模板求像素平均 MSE，取每类的最小值，再用两个类别的最小值推断最近模板类别。

本章的**粗粒度合格规则**是：与给定条件同类的最近模板 MSE 不超过 `0.01`，且在所有模板中的最近类别也与条件一致。这是预先明确的合成任务诊断，不是人类可识别性定理，也不是用于真实图像的分类器。

模板库是有限网格，数据参数却是连续采样；即使真实目标图像也不一定与某个模板逐像素相等。因此必须同时运行真实数据对照。`0.01` 是本教学实验的显式阈值，不能拿去判断更高分辨率、不同强度尺度或自然图像的质量。

### 最后检查多样性

每个类别固定输出一个标准原型，也可能全部通过上述规则，却没有学到位置和大小的分布。报告因此还检查每类前景质量（像素强度之和）、亮度质心及其变化，并与真实数据对照。这里的“质量”是 mass，不是视觉质量分数；亮度质心也不是通用物体检测器。

这些统计仍不是完整分布检验：均值和方差相同，不保证中心、尺寸、形状的联合分布一致。没有 FID、CLIP 或自然图像特征评估器参与本实验；不要将模板通过率改名为 FID 或真实图像生成准确率。

**读者完成标准：** 能完整运行、定位每类样本和原始数据、解释至少一个指标反例，并明确当前模型的不足。模型分布是否充分拟合应由实测证据判断，不因教程命令默认退出 0 就判为成功。

## 7. 练习与参考答案

### A. 同一时间为什么要广播

代码用 `t` 的形状 `B,1,1,1` 与 `B,1,16,16` 图像运算。若改为每个像素独立采样 `t`，是否仍是本章相同的训练问题？

<details><summary>答案</summary>

不是。本章时间是全图状态沿一条概率路径的位置，网络接收一个标量时间。如果每个像素有独立时间，需重新定义高维时间条件或训练路径；不能保留原推导、输入接口和 Euler 采样器就声称算法未变。广播仅展开数值，不额外采样随机时间。

</details>

### B. mean 与 sum

batch 为 64，图像为 `1,16,16`，未归约平方误差的所有元素之和为 8192。像素均值 MSE 是多少？若改成每图求和、再对 batch 求均值，结果是多少？

<details><summary>答案</summary>

全均值为 $8192/(64\times1\times16\times16)=0.5$；每图求和再平均为 $8192/64=128$，相差 256 倍。它们在固定尺寸下的最优解相同，但直接沿用同一学习率不能保证训练轨迹相同。

</details>

### C. 为什么不要给速度加 sigmoid

某像素噪声 $z=1.5$，目标强度 $y=0.2$。直线路径的目标速度是多少？如果网络输出被限制到 $[0,1]$，会发生什么？

<details><summary>答案</summary>

$y-z=-1.3$。速度必须允许负值；sigmoid 输出无法表达这个监督目标。网络预测速度与最终图像在 $[0,1]$ 内是两个不同要求。

</details>

### D. 模板合格但模式坍塌

生成器对圆盘条件永远输出一个固定圆盘，对方形条件永远输出一个固定方形。模板规则可能全部通过。应该增加哪些检查？

<details><summary>答案</summary>

先按类别检查中心位置、前景质量或估计尺寸的分布及标准差，并与独立真实数据对照；随后检查位置与尺寸的联合分布。固定原型的条件响应可以正确，但类别内变化为零。粗模板通过率只能检查图形接近某些有效模板，不能证明覆盖了目标参数范围。

</details>

### E. 改采样步数是否就是公平对照

分别运行两次训练，只把 `--sampling-steps` 从 20 改为 80，观察到第二次图片更好，能否断言原因是求解器更准确？

<details><summary>答案</summary>

需要核对训练配置、实际权重、初始噪声与条件是否完全相同。当前模块没有复用 checkpoint 的独立采样入口，因此不能仅凭两条训练命令声称冻结了模型。03 章的 `solver_study` 展示了这类控制应怎样记录；扩展本模块时应先增加可信的保存/载入与相同初始噪声验证，再研究求解器差异。

</details>

## 8. 来源、核验与迁移边界

- Lipman et al., *Flow Matching for Generative Modeling*, **ICLR 2023**，[论文](https://arxiv.org/abs/2210.02747)。条件与边缘速度的对应关系见 [03 章推导](03-flow-matching.md)；本章是独立合成图像教学实现，不复现原论文大规模图像结果。
- Meta 官方 flow matching [固定版本 `affine.py`](https://github.com/facebookresearch/flow_matching/blob/11568d37f8d5a080e12aa7b5305d9c35ae07d136/flow_matching/path/affine.py)：仿射路径与导数目标，沿用此前核对版本。
- PyTorch **v2.6.0** [MSELoss 原始实现与文档](https://github.com/pytorch/pytorch/blob/v2.6.0/torch/nn/modules/loss.py)：本轮实际读取，确认默认 `mean` 对张量全部元素求均值，不只对 batch 归约。
- Ronneberger et al., *U-Net*, **MICCAI 2015**，[论文](https://arxiv.org/abs/1505.04597)：多尺度与跳连的结构背景；本章的小型条件网络不是该分割论文网络的逐层复现。

本章数据、图形和教学代码均由本项目生成，无第三方图片归属问题。真实图像涉及更复杂的表示、语义条件、数据许可、评价和计算成本；视频还涉及跨帧联合分布。转向这些问题时请回到 [04 研究路线](04-image-video-roadmap.md) 制定新的验证协议，而不是外推本章模板得分。
